# 自适应雅思写作学习规划

## 已接入的流程

学习规划页使用 `/api/study-plan/generation-jobs`。后台任务认领成功后读取用户的学习设置和作文记录，生成未来七天的训练安排，为其中需要题目的任务分配题目，再通过一个数据库事务保存。旧版同步生成接口继续服务旧客户端；旧计划及其历史任务保留，下一次从学习规划页生成时启用新引擎。

`lib/study-plan-diagnosis.ts` 将 Task 1 和 Task 2 分开诊断。评分维度使用写作系统已有的稳定 key，旧英文名称仍可解析和显示。近 30 天作文的影响更大；七天和三十天趋势需要两边都有样本，单篇异常不会被判为持续进步。每篇作文对同一错误标签只计一次，普通语法批注不会被拆成多个具体错误。样本不足时安排诊断练习，所有分数都是估计。

`lib/study-plan/allocator.ts` 先保留用户指定日期，再填入间隔最均匀的日期。分配以训练分钟为单位：先让两项都有覆盖，再按照目标分差、较弱维度、近期练习和考试权重比较两项所缺的训练时间。Task 2 的考试权重是 Task 1 的两倍。恢复日缩短负荷，已经预留的模考仍可进行。完整练习分别需要 20、40、60 分钟；时间不够则安排专项或复习。

`lib/study-plan/question-allocation.ts` 按写作题总数计算期望来源，模考按两题计，复习不计。每个题位保存预期来源、实际来源和降级原因。候选题库按已发布、可见、可打开的题目过滤，并尽量兼顾弱题型和多样性。AI 题和模考题对保存快照，打开写作页时直接使用；AI 失败会优先选择未重复的题库题。题库不足时显示缺题并安排审题练习。

`lib/study-plan/rolling.ts` 在训练完成、跳过、修改设置、刷新诊断或新日期进入窗口时检查后续安排。没时间会降低负荷；太难时先拆成短练习；已掌握会暂时降低重复优先级；不感兴趣时尝试换一题。专项练习记录改写内容或复盘结果，并计入完成情况；单独的专项自检不会换算成 IELTS Band。计划只替换允许变动的未来任务，保护历史、完成、进行中和锁定的任务。后台租约和数据库行锁防止重复提交；滚动调整不写手动重规划配额。

## 示例：2026 年 11 月 9 日至 15 日

以伦敦时区、标准强度、目标 7.0、Task 1 估计 5.5、Task 2 估计 6.0、两项都有足够样本且 CC 较弱为输入。这是实际分配器在已存在可用题目的前提下生成的训练结构。题源取整后，四道写作题期望为三道题库题、一道 AI 题。

| 学习日 | 训练 | 总时长 |
| --- | --- | ---: |
| 11 月 9 日，周一 | Task 2 段落衔接写作 40 分钟；自检 5 分钟 | 45 分钟 |
| 11 月 10 日，周二 | Task 1 段落衔接写作 20 分钟；自检与改写 25 分钟 | 45 分钟 |
| 11 月 12 日，周四 | Task 2 段落衔接写作 40 分钟；自检 5 分钟 | 45 分钟 |
| 11 月 14 日，周六 | Task 1 段落衔接写作 20 分钟；自检与改写 25 分钟 | 45 分钟 |

四天共 180 分钟。Task 2 的限时写作共 80 分钟；Task 1 虽然限时写作共 40 分钟，但距目标更远，因此还分到 50 分钟改写和自检。其余三天休息；45 分钟不安排完整模考。

## 迁移与验证

新增迁移 `20261109201950_adaptive_study_planner.sql`，沿用现有表、RLS、锁定字段和配额规则，不改动历史迁移。在隔离的本地 Supabase 中可执行：

```sh
supabase migration up --local
supabase db query --local --file supabase/tests/adaptive_study_planner.sql
npm run typecheck
npm run lint
npm test
npm run build
npm run migration:check
```

构建需要公开 Supabase 配置；可以使用本地 URL 和本地测试占位值。SQL 集成用例覆盖重复生成、跨用户写入拒绝、旧租约重放、保护既有任务、题目快照、画像更新和配额。开发过程中通过嵌入式 PostgreSQL 运行了相关迁移与该 SQL 用例。未使用生产数据或付费 AI 接口；部署前应在配置完整的测试环境验证登录、真实题库、编辑器和反馈链路。
