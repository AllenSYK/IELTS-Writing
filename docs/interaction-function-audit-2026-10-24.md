## 范围与结论

使用提供的普通用户和管理员账号，检查本地项目的开发服务器及现有生产构建，并用内置浏览器与本机 Chrome 交叉验证。生产构建复核地址为 `http://localhost:3001`，管理端使用 `http://127.0.0.1:3001`。本报告没有验证公网部署，不能将本地复现直接等同于线上现状。

已实际检查登录、账号中心、练习选择、历史记录入口、错题本入口、学习规划入口、写作入口、帮助中心，以及管理端激活码、邮箱绑定、用户详情、真题题库、系统设置和模型配置。历史记录、错题本、学习规划及写作入口出现加载阻塞，因而未完成本轮实际作文批改、结果编辑和复习操作；相关代码问题单独标为“代码确认”。

主要问题集中在：登录后的页面可用性、保存结果的真实性，以及设置、搜索、错题和反馈等功能之间的衔接。

证据等级：**页面复现**表示实际操作可见；**代码确认**表示存在明确代码路径，未在真实账号上故意触发故障；**体验建议**表示设计改进，不等同于运行错误。P1 优先解决，P2 随后处理，P3 属于便利性改善。

本轮没有提交测试作文或反馈，没有生成、撤销或删除激活码，也没有调整账号权限、密码或管理设置。正常登录会更新登录信息，普通用户登录按已获授权记录协议同意。报告不保存密码、会话或密钥。

## 优先处理的问题

### 01 · P1 · 登录成功后，核心页面持续停在加载态

**证据：页面复现，影响范围以本地环境为准。**

- 普通账号登录成功，账号中心可显示激活状态和热力图。
- 历史记录页持续显示“正在加载内容”；本机 Chrome 与内置浏览器均复现，现有生产构建也复现。
- 错题本及学习规划入口同样停在加载态；点击“开始 Task 2”后停在“正在准备写作练习”。
- 同账号直接请求应用接口时，`/api/user/writing-records/list` 返回 HTTP 200、13 条记录，耗时约 1.49 秒；错题回填状态接口返回 HTTP 200、45 个错误模式和 112 次出现记录；学习计划接口也返回 HTTP 200。

**影响：** 数据存在，用户却无法进入主要学习流程；页面没有超时解释、重试或重新验证登录入口。

**建议：** 首先定位客户端会话初始化与页面加载状态之间的断点；为身份初始化和数据请求增加有界超时、失败状态和重试。可考虑使用服务端已验证的用户状态初始化客户端。当前证据不足以锁定唯一根因。

**代码线索：** [UserSessionProvider.tsx](/Users/allen/Documents/雅思写作系统网页端_副本2/components/auth/UserSessionProvider.tsx:80)、[user-route-cache.ts](/Users/allen/Documents/雅思写作系统网页端_副本2/lib/user-route-cache.ts:77)、[history/page.tsx](/Users/allen/Documents/雅思写作系统网页端_副本2/app/history/page.tsx:226)。会话初始化调用没有超时及异常恢复；当用户 ID 未就绪时，历史页持续显示骨架屏。开发模式还存在首次 effect 清理后，`hasFetchedRef` 阻止再次初始化的风险；这不能单独解释所有生产模式现象。

### 02 · P1 · 已有系统设置的保存请求缺少版本字段

**证据：代码确认，未提交真实设置。**

系统设置页读取并保存了 `updatedAt`，提交时却只发送 `settings`，没有发送服务端需要的 `expectedUpdatedAt`。服务端在缺少该字段时走“首次创建”分支，使用 `ignoreDuplicates: true`；已有设置行会导致返回 409 冲突。本次页面已显示存在历史保存记录，因此当前页面的正常保存路径存在明确问题。

**影响：** 管理员修改后反复看到冲突提示，即使刷新也不能解决缺少字段的问题。

**建议：** 将读取到的 `updatedAt` 作为 `expectedUpdatedAt` 提交，并提供真实并发冲突的刷新及保留编辑内容机制。

**位置：** [AdminSettingsClient.tsx](/Users/allen/Documents/雅思写作系统网页端_副本2/app/admin/settings/AdminSettingsClient.tsx:113)、[settings/route.ts](/Users/allen/Documents/雅思写作系统网页端_副本2/app/api/admin/settings/route.ts:85)。

### 03 · P1 · 草稿保存失败可能仍被当作成功处理

**证据：代码确认，未故意损坏真实草稿。**

`saveAllDrafts` 捕获错误后只设置错误状态，没有将失败抛出；`flushDraftSave` 随后仍更新“已保存内容”的标记。`saveNow` 在等待上述函数后无条件提示“草稿已保存”，退出流程也会继续离开页面。

**影响：** 用户收到的保存反馈可能与真实结果不符；内容未变化时也可能不再自动重试。在本地存储或远端保存失败的情况下，存在恢复困难和内容丢失风险。本轮没有验证实际丢稿。

**建议：** 保存函数返回明确结果或抛出异常；只在成功后更新已保存标记，退出前区分本地保存成功、云端同步成功和失败，失败时保留编辑器并允许重试。

**位置：** [write/page.tsx](/Users/allen/Documents/雅思写作系统网页端_副本2/app/write/[mode]/page.tsx:377)、[保存完成标记](/Users/allen/Documents/雅思写作系统网页端_副本2/app/write/[mode]/page.tsx:455)、[保存与退出](/Users/allen/Documents/雅思写作系统网页端_副本2/app/write/[mode]/page.tsx:829)。

### 04 · P1 · “保存到错题本”没有接入实际错题本

**证据：代码确认。**

结果页的“保存到错题本”调用只把作文 ID 写入本地存储。错题本页面读取的是 `/api/study-plan/errors` 的服务端错误模式；全仓库没有找到该本地收藏标记的读取入口。服务端存在自动提取错误的另一条流程，但按钮没有与该流程连接。

**建议：** 明确区分“收藏作文”和“提取错误”；按钮应写入对应服务端数据，完成后提供可定位到该作文错误的入口。

### 05 · P1 · 用户反馈没有形成可操作的处理流程

## 建议实施顺序与验收

1. **恢复核心页面与可靠保存。** 同账号登录、刷新、从站外进入历史/错题/写作页面均能结束加载；失败有明确提示和重试。模拟本地及远端保存失败时，不出现错误成功提示，重开可恢复已确认保存的内容。
2. **修复设置与管理入口。** 已有设置可正常保存；默认 30 天应反映到生成弹窗；总览能打开，题库搜索不存在关键词时返回空结果；时间及分页遵循已保存配置。
3. **接通错题与反馈流程。** 从结果页加入错题后能立即定位相应内容并跨设备可见；用户反馈在管理端可查、可处理，用户能查看进度。
4. **统一交互与文案。** 登录恢复来源页面；练习只保留一致的开始动作；草稿可辨认；帮助与诊断信息对应当前网页版。

发布前仍需在实际公网部署进行一轮验证，覆盖完整模考、上传题目、批改等待与取消、结果修改、错误复习，以及移动端编辑器。它们没有在本轮被证明全部可用。
